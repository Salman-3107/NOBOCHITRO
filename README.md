# NOBOCHITRO 🎬

NOBOCHITRO is a full-stack movie tracking and social platform — think Letterboxd — where users log the movies they watch, rate and review them, keep a watchlist, journal their movie-watching habits, follow other users, complete challenges, and compare taste with friends. It ships with its own JWT-based authentication, an Oracle PL/SQL backend (triggers, functions, and stored procedures), and a full admin dashboard.

## Features

- **Accounts & auth** — registration/login with bcrypt-hashed passwords, JWT access tokens with revocation support (logout invalidates the token via a `RevokedToken` table), and route-level protection for the entire API.
- **Movie catalogue** — browse, search, and view movie details (cast, genres, country, TMDB poster art).
- **Reviews & ratings** — rate and review movies; average ratings are computed in the database.
- **Watchlist / Bucket List** — save movies to watch later.
- **Journal** — log entries for movies you've watched, tied into challenge progress.
- **Social features** — follow other users, post to a community feed, like/comment on posts, and get notifications (new follower, likes, comments) generated by database triggers.
- **Challenges & XP** — complete curated challenges to earn XP and badges, with a leaderboard.
- **Taste Match** — a compatibility score between two users based on how similarly they rate movies.
- **Movie Passport & Stats** — per-user breakdowns by genre, country, director, month, and rating.
- **Recommendations** — suggested movies based on a user's favourite genres.
- **Admin dashboard** — manage movies, genres, people, users, reviews, posts, comments, challenges, and view platform-wide analytics and audit logs.

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | React 19, React Router 7, Vite |

## Prerequisites

- Node.js 18+ and npm
- An accessible Oracle Database instance (local, Docker, or Oracle Autonomous DB)
- A [TMDB API access token](https://www.themoviedb.org/settings/api) (only needed if you run the poster/detail sync scripts)

## Setup

### 1. Database

Run the SQL scripts against your Oracle instance **in this order**:

1. `database/create_tables.sql` — base schema
2. `database/sequences.sql` — ID sequences
3. `database/constraints.sql` — foreign keys / checks
4. `database/plsql_objects.sql` — triggers, functions, stored procedures
5. The incremental migrations, as needed for your schema version: `add_isadmin.sql`, `add_userfollow.sql`, `add_revoked_token.sql`, `add_notifications.sql`, `add_profile_cover.sql`, `add_tmdb_details.sql`, `admin_dashboard_extensions.sql`
6. `database/admindeclaration.sql` — promote a user to admin
7. Seed data (optional but recommended): `database/seed_data.sql`, `database/famous_movies_seed.sql`, `database/famous_movie_genres.sql`

`database/fix_appuser_missing_pk.sql` and `database/repair_corrupted_famous_catalogue.sql` are one-off repair scripts — only run them if you hit the specific issue they describe. See `database/INTERNATIONAL_MOVIE_CATALOGUE.md` for details on the international movie catalogue.

### 2. Backend

```bash
cd backend
npm install
```

Create a `backend/.env` file:

```env
# Oracle connection
DB_USER=your_db_user
DB_PASSWORD=your_db_password
DB_CONNECT_STRING=host:port/service_name

# Auth
JWT_SECRET=a_random_string_at_least_32_characters_long

# Server
PORT=5000
CORS_ORIGINS=http://localhost:5173,http://localhost:4173

# Optional — only needed for the TMDB sync scripts
TMDB_ACCESS_TOKEN=your_tmdb_v4_access_token
```

Start the API:

```bash
npm start
```

The server boots the Oracle connection pool first and refuses to start without a valid `JWT_SECRET` (must be ≥ 32 characters).

Other backend scripts:

```bash
npm run sync-posters        # Fetch/store real TMDB poster URLs for movies
npm run sync-details        # Fetch/store extended TMDB movie details
npm run seed:international  # Seed the international movie catalogue
```

### 3. Frontend

```bash
cd frontend
npm install
npm run dev
```

The dev server runs on `http://localhost:5173` by default (Vite) and expects the backend to be reachable at the URL configured in `frontend/src/api`.

Other frontend scripts:

```bash
npm run build     # Production build
npm run preview   # Preview the production build
npm run lint       # Lint with oxlint
```

## API Overview

All endpoints are mounted under `/api` and, except for `POST /api/auth/register` and `POST /api/auth/login`, require a valid `Authorization: Bearer <token>` header — the auth gate is applied once in `server.js` ahead of every router, so no individual route can be left unprotected by mistake.

Route groups: `auth`, `movie`, `review`, `bucketList`, `post`, `follow`, `journal`, `tasteMatch`, `passport`, `challenge`, `admin`, `search`, `recommendation`, `leaderboard`, `activity`, `notification`, `stats`.

## Database Design Highlights

- **Triggers** — audit logging on review edits/deletes, automatic notifications on follows/likes/comments, and auto-completion of challenges when progress hits its target.
- **Functions** — `FN_MOVIE_AVG_RATING`, `FN_TASTE_MATCH_SCORE`, `FN_USER_TOTAL_XP`.
- **Stored procedures** — `PROC_ADD_TO_WATCHLIST`, `PROC_PUBLISH_CHALLENGE`, `PROC_SET_USER_ROLE`.
- **Transactions** — all writes run with `autoCommit` off, with an explicit `commit()` on success and `rollback()` on error.

See `CHECKLIST_COMPLIANCE.md` for a full map of these features to their exact file and function locations, and `ERD/` for the entity-relationship diagram.
